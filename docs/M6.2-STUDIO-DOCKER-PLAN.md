# M6.2 Studio Docker 생성기

작성일: 2026-09-18

상태: 완료 · 로컬 Studio→Crosswalk 통합 E2E 통과

## 목표

Studio에서 Registry, VM, Container를 설계하고 `crosswalk-docker` 생성기를 선택해 Crosswalk `deploy docker`가 직접 읽을 수 있는 패키지를 만든다.
Studio는 설계·검증·패키지 생성까지만 담당하고, SSH 연결·Registry 인증·원격 Docker 변경은 Crosswalk가 담당한다.

## 책임 경계

```text
Studio topology editor
  └─ Blueprint v1 (registry + vm + container + placement)
       └─ Studio crosswalk-docker generator
            └─ ZIP: deploy.yml
                 └─ Crosswalk deploy docker
```

- Studio에는 Registry token 값을 저장하지 않는다. 실행 시 사용할 환경변수 이름(`tokenEnv`)만 Blueprint와 패키지에 기록한다.
- Container image는 tag가 없는 repository와 SHA-256 digest를 별도 필드로 입력한다.
- Docker Engine 설치 여부와 설치 정책은 Studio가 결정하지 않는다. Crosswalk의 preflight와 명시적 bootstrap 계약을 따른다.
- Docker 패키지에는 서버로 전송할 artifact가 없으므로 `deploy.yml`만 포함한다.

## 모듈 구조

- `studio/backend/internal/generator/crosswalkdocker`: Blueprint를 Crosswalk Docker chart와 ZIP으로 변환
- `studio/backend/internal/domain`: Container/Registry/placement 구조 및 배포 옵션 검증
- `studio/backend/internal/service/delivery.go`: 생성기 선택과 immutable generation/package 수명주기
- `studio/features/topology`: Container 편집, VM 배치, Registry credential reference 입력
- `studio/features/generation`: capability 기반 생성기 선택, 검증, 이력, 패키지 미리보기
- `studio/scripts/e2e-studio-crosswalk.mjs`: VM·Docker·Compose 패키지의 실제 Crosswalk dry-run 호환 검증

## 오류 케이스 검토

1. Registry token 원문이 저장되거나 ZIP에 노출됨: UI와 schema는 `tokenEnv`만 받으며 생성 결과도 `token_env` 이름만 출력한다.
2. mutable tag 또는 잘못된 digest로 배포됨: repository에는 tag/digest를 금지하고 소문자 SHA-256 digest를 필수화한다.
3. Container가 Kubernetes나 잘못된 대상에 배치됨: Container workload는 VM의 `container` mode placement 하나만 허용한다.
4. 동일 VM host port가 충돌함: process/container workload를 함께 계산해 저장·생성 전에 거부한다.
5. 환경변수에 개행이나 NUL이 포함됨: 구조 검증 단계에서 차단해 생성 YAML과 원격 env-file 경계를 보호한다.
